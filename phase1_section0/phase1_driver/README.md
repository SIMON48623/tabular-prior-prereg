# Phase 1 execution driver

This directory is the hash-frozen Phase 1 driver. It imports registered code
from the final registration package and refuses execution unless the registered
inputs, this driver, the environment lock, the assignment, the requested work
unit, the actual host hardware, and all required local model weights pass their
checks. Pool fitting additionally requires a separate authorization file whose
only content is `PHASE1_AUTHORIZED`.

## Modules

- `admission.py`: retained 214 admission and deterministic, timing-model-based
  two-host assignment implementation. The accepted `lr_reference_214.csv` and
  `host_assignment.csv` are not regenerated by this revision.
- `config.py`: registered scope, schemas, seeds, one-thread settings and GPU
  deterministic settings, including `CUBLAS_WORKSPACE_CONFIG=:4096:8`.
- `data.py`: input preparation. `prepare_ordinal_views` supplies TabPFN input.
  `prepare_tabicl_views` uses that exact ordinal output and converts categorical
  columns to pandas `category`. `prepare_ftt_views` implements numeric median
  imputation plus standardization and categorical mode imputation plus one-hot;
  FT-Transformer receives all columns as continuous features and
  `cat_cardinalities=[]`.
- `cpu_models.py`: traditional-model boundary and post-registration deviation
  D1 described below.
- `gpu_models.py`: explicit local-weight foundation-model construction and
  FT-Transformer training/inference. Validation and test inference are batched
  at 1,024 rows; sigmoid is evaluated in float64.
- `runtime.py`: automatic manifest, pipeline, generator, lock, assignment,
  weight, machine-derived host and hardware attestation; offline environment
  and socket guard. The whole registration `MANIFEST.sha256` is checked. A
  complete `cleaned_data` hash ledger is generated once per machine and then
  fully rechecked at every scheduler start.
- `planner.py`: exact registered plan, including the 238 `target_region=True`
  datasets read from `frozen/stratifier_v2.csv` and an `INJECT_REPS` assertion.
- `execution.py`: one plan unit, model retries, probability validation,
  per-model failure recording, Phase 0b-compatible M6 preparation and columnar
  prediction payloads.
- `checkpoints.py`: canonical paths, per-unit locks, PID-specific temporary
  files, fsync-backed identity-bound atomic checkpoints, invalid-checkpoint
  quarantine, explicitly approved migration manifests, and row/column
  conversion.
- `aggregate.py`: plan-exact completeness, identity and uniqueness validation,
  followed by streaming aggregation by `(module, dataset)`.
- `reporting.py`: record-schema helpers. Final `run_log.txt` and per-host
  `environment_run.json` are reconstructed from checkpoint payloads during
  aggregation, rather than being trusted as mutable side effects. A host maps
  to a list of distinct environment records, so split M2 dispatches,
  multi-module aggregation and approved migrations can coexist. Per-dispatch
  arguments such as `--stages` are deliberately excluded from the records.
- `model_free_checks.py`: 478-dataset marginal-AUROC reproduction and the M2
  concentrated-signal sanity check. It fits no model.
- `scheduler.py` and `schedule_*.sh`: 32 persistent workers on each CPU host and
  one persistent GPU worker. `--stages` accepts only registered Section 1
  stages in registered order (there is no synthetic `M2` shortcut), while
  `aggregate.py --modules` permits independent module delivery. The scheduler
  builds the plan and performs registered/driver/data/weight hashes only once,
  takes the machine lock before scanning and quarantining checkpoints, skips
  valid completed units before submission, and reuses workers instead of
  starting an interpreter per unit. Each worker owns at most one known unit,
  is rebuilt after a crash or timeout, and is recycled after 200 completed
  units. `PYTHONHASHSEED=13` and thread/offline
  variables are exported and shell-checked before Python starts.
- `host_registry.json`: section-0 registration of actual machine hostnames to
  assignment roles. The scheduler derives the hostname itself; no environment
  variable or command-line flag can claim another host.
- `dry_run.py`: model-free pool flow test using only a fixed 0.5 fake model; its
  temporary checkpoints and aggregates are deleted before delivery.
- `smoke.py`: two toy variants × ten models, no performance metrics. It audits
  actual model-boundary matrices for NaN, includes a held-out fold with a
  missing training level and an unseen level, records each model's handling,
  and keeps socket protection enabled for all ten models.
- `tests/`: all unit and contract tests; these files are part of the driver hash.

## D1 — post-registration XGBoost deviation

The registered `phase0c/phase1_pilot.py::cpu_fit_predict` creates training and
test pandas categorical columns independently. When the held-out fold contains
an ordinal value absent from training (including `OrdinalEncoder`'s `-1`),
XGBoost rejects prediction before returning probabilities.

D1 leaves the registration package unchanged. For XGBoost units with
categorical columns, `cpu_models.xgb_d1_fit_predict` reproduces the registered
XGBoost branch, except that each held-out categorical column is constructed
with the corresponding training column's categories. Values outside that set
are explicitly replaced with `NaN` and therefore enter XGBoost as missing. For
datasets without categorical columns, the registered `cpu_fit_predict` is
called directly.

The unit test and smoke precheck establish both required cases:

1. with no unseen held-out level, D1 and the registered path are bitwise equal;
2. with no unseen value but a missing middle category level, D1 remains
   bitwise equal to the registered path;
3. with a missing training level and a genuinely unseen held-out level, D1
   completes and records `D1 training categories; unseen -> NaN`.

The final `smoke_phase1.log` records the equivalence result and unseen-level
handling for both toy variants.

## Row identity and failed predictions

`cleaned_data/*.parquet` deliberately has no `row_index` column. `row_index` is
defined only as the zero-based physical row position in the registered parquet
file. The driver rejects a parquet file that unexpectedly contains a column of
that name; there is no fallback or inference from another field.

Each successful M1/M2/M4 metric row must have exactly `n_test` prediction rows.
A failed model retains its metric row with `status=failed` and its reason, but
has zero prediction rows. Aggregation checks both rules, in addition to global
metric/prediction key uniqueness, so failed rows are not mistaken for missing
plan units and successful predictions cannot silently disappear.

## Offline and integrity rules

Foundation weights are read only from the paths registered in
`phase0c_outputs/environment_phase1.json`. The GPU scheduler hashes all three
weights once before its persistent worker is created, and every constructed
foundation estimator must match the frozen SHA-256 of the tensor parameters
actually loaded from each registered weight. The attestation is bound to the
registered weight-file SHA-256 and is performed once per model in each
persistent process; a constructor path alone is not accepted as proof.
`HF_HUB_OFFLINE=1`,
`TRANSFORMERS_OFFLINE=1`, `HF_DATASETS_OFFLINE=1` and a socket guard prohibit
network fallback. Attestation or weight-loading failure exits before a
checkpoint is written. No token, password, remote API call, model performance
result or prediction is stored in the driver itself.

CUDA out-of-memory and Python `MemoryError` are model failures: cache is
cleared, the model is retried once, and a second failure is recorded while the
stage continues. A destroyed/illegal CUDA context is process-fatal. Its attempt
is persisted, the persistent worker is replaced, and the unit is retried once;
two consecutive fatal attempts create a failed-unit checkpoint instead of an
infinite rerun. FT-Transformer is a separate M1 `ftt` work unit, so its failure
cannot erase or invalidate the three foundation-model results.

The unit deadline is ten times the registered `compute_projection` estimate
multiplied by the preflight EBM ratio, with a one-hour minimum. Timeout starts
only after the child acknowledges the unit; worker startup has a separate
300-second limit. Terminal unit failure still emits `status=failed` metric rows
for every model owned by that unit and, for M1, the corresponding failed inner
selection rows. Model-level failures completed under Section 7 do not advance
the consecutive-unit-failure counter; fatal/unit failures do, and 20 in a row
stop the stage.

## Checkpoint migration and failure-stop rules

Changing the driver changes every expected checkpoint identity. Old checkpoints
are rejected by default. Reuse is allowed only when an external, commissioning-
party-approved JSON migration list names the exact old hash, new hash and every
applicable task key; each accepted migration is copied into `run_log.txt`.
Malformed checkpoints are moved to the runtime quarantine and recomputed.
Readable but unapproved identities stop execution. A host-wide exclusive lock
permits only one scheduler on that machine. A stage stops after 20 consecutively
failed units and leaves its machine-local failure ledger for the stop report.

## Pool dry run and fault injection

`dry_run.py` selects three pool datasets for each of M1, M2, M4 and M6 plus two
M5 cells, then exercises data loading, registered variant generation,
identity-bound checkpointing, per-module aggregation and all aggregate
self-checks with a fixed probability of 0.5. It fits or loads no real model and
deletes its temporary checkpoint tree. The same run deliberately confines one
model failure to LR, crashes one M2 worker once, and times out one M4 worker
once. The crash and timeout are attributed to their active units, their workers
are rebuilt, and the retries use the normal production deadline. Results are
reported in `dry_run_report.md` and `fault_injection_report.md` outside the
frozen driver.
