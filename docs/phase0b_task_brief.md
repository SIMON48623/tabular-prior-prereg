# 任务简报：Phase 0b — 扩池、家族标注、分层变量比选

> 整份交给执行方。需要 Python 与网络。预计半天到一天。不需要 GPU。
> 本轮是 Phase 0 的修订重跑，上一轮的脚本和环境可复用。

---

## 0. 上一轮发现了什么，为什么要重跑

上一轮跑了 136 个候选、纳入 116 个，结论是"通过"。但复核原始数据发现两个问题，都会导致正式研究被拒：

**问题一：伪重复占一半。**116 个纳入数据集中有 56 个属于 `fri_c*` 系列——同一个 Friedman 合成生成器的参数网格（c1–c4 × n∈{250,500,1000} × p∈{5,10,25,50}）。它们不是独立样本。上一轮的去重规则只按 (名称, n, p) 三元组，没有按生成器家族，所以它们全部通过了。这是简报的疏漏，不是执行错误。

在最关键的目标区域（整体可预测性中等、单变量主导），42 个数据集里有 30 个是 `fri_c*`，只有 12 个是独立真实数据集。混合效应回归会被一个合成生成器的性质主导。

**问题二：分层变量 SCR 的操作化不稳定。**SCR = (auc_best−0.5)/(auc_lr−0.5)，分母趋零时爆炸：LR lift 在 [0,0.10) 的四个数据集，SCR 范围是 [−0.24, 1.81]。116 个里 14 个 SCR>1，1 个为负。而且低 SCR 那一端几乎全是逻辑回归已经解满的玩具数据集（kr-vs-kp auc_lr=0.994、tic-tac-toe 0.991、prnn_crabs 1.000），与我们关心的"信号弱且分散"是完全不同的结构。

本轮目标：**扩大独立数据集池、标注来源家族、同时计算四种候选分层变量并比较其稳定性。**

---

## 1. 最重要的约束（与上一轮相同）

**本轮仍然禁止运行任何模型对比实验。**

不跑 TabPFN、CatBoost、XGBoost、LightGBM、随机森林或任何树模型。不计算任何模型间性能差值。**唯一允许拟合的模型是逻辑回归**，仅用于计算参照全模型 AUROC。

原因不变：正式研究采用预注册设计，一旦本阶段产出模型对比结果，这些数据集永久失去预注册资格。

---

## 2. 扩大候选池

**目标：候选 500–800 个，最终纳入的独立真实数据集 ≥ 150 个。**

来源，按优先级依次抓取，允许重叠后去重：

1. **OpenML-CC18** benchmark suite（study_id=99）
2. **OpenML AutoML Benchmark** 分类套件
3. **OpenML 全库**按 openml_id 升序扫描，直到候选总数达标
4. **UCI** 中未被 OpenML 收录的常用二分类临床/生物医学表格（可选，若前三项已达标可略过）

筛选规则与上一轮**完全一致，不得调整**：

| 条件 | 阈值 |
|---|---|
| 任务类型 | 二分类 |
| 样本量 n | 200 ≤ n ≤ 10000 |
| 特征数 p | 5 ≤ p ≤ 100 |
| 少数类比例 | 5% ≤ rate ≤ 50% |
| 单列缺失率 | 保留列缺失 ≤ 30%，删后 p 仍须 ≥ 5 |
| 结构 | 排除时间序列、图像/文本衍生高维稀疏表 |
| 标识列 | 删除唯一值数 ≥ 0.95×n 的非数值列，或列名含 id/index/key |
| 全模型信号 | auc_lr ≤ 0.52 者标记为"无可用信号"，SCR 记 NaN 并排除出分布统计 |

## 3. 来源家族标注（本轮新增，必做）

给每个数据集加一列 `family`，标注其生成来源。规则：

**合成生成器网格**——名称匹配同一模式、仅参数不同的，归为一个家族：
- `fri_c\d+_\d+_\d+` → `fri_c`
- `monks-problems-\d` → `monks`
- 其他形如 `<基名>_<数字>_<数字>` 且基名在池中出现 ≥ 3 次的 → 以基名为家族名

**同源真实数据集**——同一原始数据的不同版本或子集（如 heart-h / hungarian、prnn_fglass / glass）→ 归为一个家族，家族名取最早版本的名称。

**其余** → `family = 'independent'`，每个数据集自成一家族（family 值填其自身名称）。

同时输出一列 `family_size`：该家族在纳入集中的成员数。

**判定用的是独立家族数，不是数据集数。**

## 4. 四种候选分层变量（本轮核心）

对每个数据集，在同一次五折嵌套流程中计算以下全部量。

### 4.1 单变量边际 AUROC —— 全部保存，不只是最大值

对每个特征 j，在**训练折内**确定方向、在 **held-out 折**评估，五折汇总得到 `auc_j`。

**把全部 `auc_j` 存成一个 JSON 文件**（见输出规格 5.2）。这是本轮相对上一轮最重要的增量——没有它，后三个分层变量算不出来。

类别型特征沿用上一轮的处理：训练折内排序类别编码。跨折汇总沿用上一轮的折内经验百分位映射（单调、不使用 held-out 标签）。这两条上一轮做得对，保持不变。

### 4.2 四个分层变量

设 `lift_j = max(auc_j − 0.5, 0)`，`L = Σ_j lift_j`。

| 变量 | 定义 | 说明 |
|---|---|---|
| `SCR` | (auc_best − 0.5) / (auc_lr − 0.5) | 上一轮的定义，保留作对照 |
| `gap` | auc_lr − auc_best | 多变量建模相对最强单变量的增量 |
| `N_eff` | L² / Σ_j lift_j² | **有效贡献特征数**。=1 表示信号完全集中于一个变量；越大越分散 |
| `N_eff_norm` | N_eff / p_used | 归一化版本，去除特征数影响 |

**`N_eff` 是本轮推荐的主候选**，因为它只用单变量边际统计量、**不含任何全模型项**，因此在构造上与后续的模型对比量 Δ 独立。这一点前三个都做不到。

**不要裁剪任何一个变量的取值。**SCR 可能 >1 或为负，N_eff 可能接近 1，如实记录。

## 5. 输出规格

在 `phase0b_outputs/` 下产出。

### 5.1 `datasets_stratifiers.csv`

每行一个数据集：

```
openml_id, name, version, source_suite, family, family_size,
n, p_raw, p_used, minority_rate,
n_dropped_missing_cols, n_dropped_id_cols,
best_feature_name, best_feature_fold_consistency,
auc_best_feature, auc_lr,
SCR, gap, N_eff, N_eff_norm,
excluded_reason
```

`source_suite` 记录来自 CC18 / AMLB / openml-scan / UCI。被排除的数据集也留在表里，注明原因。

### 5.2 `marginal_aucs.json`

```json
{ "<openml_id>": { "feature_name": auc_j, ... }, ... }
```

只含纳入统计的数据集。这份文件后续正式研究会反复用到，务必完整。

### 5.3 `stratifier_report.md`

第一行写判定结论（见第 6 节）。正文包含：

- 候选数 / 纳入数 / 排除数及各排除原因计数
- **独立家族数**，以及最大的五个家族及其成员数
- 四个分层变量各自的描述统计（min / Q1 / 中位数 / Q3 / max）
- **稳定性比较表**：每个分层变量与 `auc_lr`、`n`、`p_used`、`minority_rate` 的 Spearman ρ 及 p 值。与 `auc_lr` 的 |ρ| 越小越好（说明未被整体难度污染）
- **目标区域计数**：定义为 `auc_lr ∈ [0.60, 0.85]`（有信号但未饱和）。报告该区域内的数据集数与**独立家族数**，并按每个分层变量的三分位进一步细分
- 四张直方图，每个分层变量一张，合成家族与独立数据集**用不同颜色分别叠加显示**

### 5.4 `stratifier_hists.png`

上述四张直方图，2×2 布局，图例区分合成家族与独立数据集。

### 5.5 `run_log.txt`

每个候选一行：openml_id、来源套件、是否纳入、失败原因。下载或解析失败必须记录，不得静默跳过。

### 5.6 `environment.json`

Python 与各库版本、随机种子、折划分参数、筛选规则实际取值、家族标注规则实际取值。

## 6. 判定标准（事先写死）

| 条件 | 结论 |
|---|---|
| 目标区域（auc_lr 0.60–0.85）内**独立家族数 ≥ 30** | **通过**，Phase 1 可启动 |
| 独立家族数 15–29 | **部分通过**，需继续扩池 |
| 独立家族数 < 15 | **不通过**，报告并停止 |
| 某分层变量与 auc_lr 的 \|ρ\| ≤ 0.25 且取值范围有界（无 >2 或 <0 的离群） | 该变量**可作为主分层变量** |
| 四个变量全部不满足上一条 | **警告**，需另行设计分层变量 |

结论写在 `stratifier_report.md` 第一行。

## 7. 自检

1. `family` 列中，`fri_c` 家族的 `family_size` 应显著大于 1；若所有数据集的 family_size 都是 1，说明家族标注未生效，停下检查。
2. `marginal_aucs.json` 中每个数据集的特征数应等于该数据集的 `p_used`。
3. 随机抽 3 个数据集，验证 `N_eff` 手算与脚本一致；再验证若把某个数据集的所有 lift 设为相等，`N_eff` 应等于有正 lift 的特征数。
4. 验证 `auc_best_feature` 等于该数据集 `marginal_aucs.json` 中的最大值（允许 1e-9 误差）。
5. 确认全程未调用任何树模型或 TabPFN，未计算任何模型间差值。
6. 确认四个分层变量均未被裁剪。

---

## 8. 不要做的事

- 不跑模型对比（见第 1 节）。
- 不在看到结果后调整筛选规则或家族标注规则去改善覆盖。规则预先固定；覆盖不足本身就是要报告的结论。
- 不裁剪分层变量取值。
- 不静默跳过失败数据集。
- 不因为某数据集"不像临床数据"而排除——非临床数据集是对照组，正式研究需要它们检验结论是否临床特有。
- 不要为了凑够独立家族数而放宽筛选阈值。数量不够就如实报告"部分通过"。
